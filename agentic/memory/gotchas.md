# Gotchas

Repo-specific traps and known gaps. Verify before acting; if a gap is closed, move it to `verified-facts.md` or delete it.

- **Login is unthrottled.** `authLimiter` is defined and exported in `backend/src/middlewares/rateLimiter.js` but is **not** applied to any route (grep finds only the definition + export, no import sites). Treat login/credential endpoints as unprotected against brute force until this is wired in.
- **Backend Jest and frontend ESLint are advisory in PR CI, not blocking.** `ci.yml` blocks backend `prettier` + ESLint and frontend `tsc`+build; backend Jest (legacy `/v1` `auth`/`user` integration tests) and frontend ESLint (`no-explicit-any`, `jsx-a11y`) run with step-level `continue-on-error` (job stays green, warning annotation). There is no Playwright job on PRs. Agents/authors must run `npm test` (backend) and Playwright (`.agents/`) locally and state how it was verified in the PR body. Remove `continue-on-error` as each is fixed.
- **Plugins execute unsandboxed in the browser.** Plugin code runs with page-level privileges, not in an iframe/Web Worker sandbox. Treat plugin input as trusted-but-audited, not untrusted.
- **`.env*` is gitignored but easy to leak.** Don't paste values into PRs, logs, or commit messages. `.agents/.env` and `instance-setup/.env.prod` are both gitignored.
- **`down.sh` is destructive on prod.** It tears down the Compose stack; never run it against a production instance without explicit confirmation (see `RULES.md`).- **Plugins get `react-dom/client` as `window.ReactDOM` — no `createPortal`.** `PluginPageRender.tsx` sets `window.ReactDOM` to the `react-dom/client` module (only `createRoot`/`hydrateRoot`). A plugin built with `react-dom` externalized to `ReactDOM` that calls `ReactDOM.createPortal` gets `undefined`. Render overlays with a separate `createRoot` on a `document.body` element instead (see the extensions `runtime-panel` plugin's `BodyLayer`).
- **The Code tab saves into `modelStore`, not the prototype query.** `PrototypeTabCode` writes saved code with `setActivePrototype` and doesn't invalidate `['prototype', id]`, so anything fed from `useCurrentPrototype()` runs/shows the previously saved code until a refetch. Runtime-facing consumers (e.g. `PrototypeRuntimePanel`) must prefer `useModelStore().prototype`.
- **Dev backend restarts on plugin upload:** `npm run dev` runs `nodemon --ignore 'data/*'`, so extracting a zip into `backend/static/plugin/` restarts the backend. In E2E, the request right after a ZIP upload (e.g. `plugin-management.spec.ts:78`) gets `socket hang up` and the next test can load a blank page. Run ZIP-upload specs on their own, or start the backend with `static/*` ignored too.
